## 1. Pourquoi passer en Mode Protégé ?

En Real Mode (16 bits), le processeur n'a accès qu'à 1 Mo de RAM (`2^20`), n'a aucune protection mémoire (n'importe quel programme peut écraser le BIOS ou le Kernel) et fonctionne sur 16 bits.

Le **Mode Protégé 32 bits** apporte :

- Un espace d'adressage de **4 Go de RAM**.
- La protection de la mémoire (Segmentation et Paging).
- L'exécution de code C natif en 32 bits.

## 2. Configuration de la Global Descriptor Table (GDT)

En mode protégé, les registres de segment (`CS`, `DS`, `SS`...) ne contiennent plus des adresses physiques directes, mais des sélecteurs qui pointent vers des descripteurs définis dans la **GDT**.

```nasm
gdt_start:
    ; Descripteur Nul (Obligatoire)
    dd 0x0
    dd 0x0

gdt_code:
    ; Segment de Code (Base=0, Limit=0xFFFFF, Access=0x9A, Flags=0xCF)
    dw 0xffff
    dw 0x0
    db 0x0
    db 10011010b
    db 11001111b
    db 0x0

gdt_data:
    ; Segment de Données (Base=0, Limit=0xFFFFF, Access=0x92, Flags=0xCF)
    dw 0xffff
    dw 0x0
    db 0x0
    db 10010010b
    db 11001111b
    db 0x0

gdt_end:

gdt_descriptor:
    dw gdt_end - gdt_start - 1
    dd gdt_start
```

## 3. Basculement en Mode 32 Bits

1. Désactiver les interruptions (`cli`).
2. Charger la GDT avec `lgdt [gdt_descriptor]`.
3. Activer le bit 0 du registre de contrôle **`CR0`**.
4. Effectuer un saut lointain (`far jump`) pour vider le pipeline d'instructions 16 bits et recharger `CS` !

```nasm
switch_to_pm:
    cli
    lgdt [gdt_descriptor]
    mov eax, cr0
    or eax, 0x1
    mov cr0, eax
    jmp 0x08:init_pm    ; 0x08 = offset du segment de code dans la GDT

[bits 32]
init_pm:
    mov ax, 0x10        ; 0x10 = offset du segment de données dans la GDT
    mov ds, ax
    mov ss, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    mov esp, 0x90000    ; Initialiser le pointeur de pile (Stack)
    call kernel_main    ; Appeler notre fonction C !
```

## 4. Notre Premier Kernel en C (`kernel.c`)

En bare-metal, la fonction `printf` n'existe pas. Nous écrivons directement dans le buffer vidéo VGA situé à l'adresse physique **`0xB8000`** :

```c
// kernel.c
void kernel_main(void) {
    // Pointeur vers la mémoire vidéo textuelle (80x25 caractères)
    volatile char* vga_buffer = (char*) 0xB8000;
    const char* str = "ZNote OS Kernel v0.1 - Running in 32-bit Protected Mode!";

    int i = 0;
    while (str[i] != '\0') {
        vga_buffer[i * 2] = str[i];        // Octet de caractère ASCII
        vga_buffer[i * 2 + 1] = 0x0A;      // Octet d'attribut de couleur (Vert clair sur fond noir)
        i++;
    }
}
```

## 5. Compilation Cross-Compiler

```bash
# Compilation du Kernel C sans bibliothèque standard C (freestanding)
i686-elf-gcc -c kernel.c -o kernel.o -std=gnu99 -ffreestanding -O2 -Wall

# Édition de liens pour créer une image binaire finale
i686-elf-ld -o kernel.bin -Ttext 0x1000 kernel.o --oformat binary
```

Nous disposons maintenant d'un véritable noyau 32 bits démarré par notre propre bootloader !
